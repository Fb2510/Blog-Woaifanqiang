Mihomo 面板显示断开怎么办？控制端口、密钥与浏览器报错排查

小六2026-10-11— 次阅读
机场指南

Mihomo 面板能打开，却显示断开或读不到节点，先检查面板连接的控制接口。页面文件加载成功，不代表内核 API 已连接；代理还能上网，也不能证明面板地址、密钥和浏览器请求都正确。把页面、控制接口和代理流量分开排查，才能避免反复换节点却没有变化。

作者：小六｜资料核对日期：2026年10月11日。本文适用于连接自己 Mihomo 内核的网页面板；客户端内置界面的实现可能不同，设置入口以软件说明为准。

一、三个地址，先分清用途

地址或端口 用途 常见误填
面板页面地址 加载按钮、图表等网页内容 认为页面能打开就代表内核已连接
控制接口地址 查询内核状态、规则和策略组 把 HTTP 或混合代理端口填进面板
HTTP、SOCKS 或混合代理入口 接收应用需要代理的请求 当成面板的管理 API

Mihomo 的 external-controller 是控制 API 监听地址，external-ui 可提供面板静态文件，文档说明其访问路径为 API 地址下的 /ui。见官方全局配置。代理入口则由代理端口文档另行说明。

不要把教程中的端口当成所有客户端的固定值。先查看当前生效配置，再核对面板保存的协议、主机和端口；数字相同或页面名称相似，都不能替代这一步。

二、先记录浏览器的真实错误

打开浏览器开发者工具，查看网络请求和控制台，再重新连接面板。菜单名称按浏览器而定，重点记录失败请求的目标、时间、状态或错误类型，暂时不导出整份网络记录。

观察结果 下一步方向
连接被拒绝、超时 内核是否运行、控制地址与监听范围是否一致
控制 API 返回 401 请求是否携带该 API 所需的有效授权
控制台明确报告 CORS 核对页面来源与 API 的跨来源响应
报告 Mixed Content 核对页面和请求的协议及地址类型
版本请求成功，只有部分功能失败 分别检查对应请求、接口和面板兼容性

这张表用于选排查方向。普通“Failed to fetch”提示不能单独证明 CORS、节点失效或密钥错误，必须继续看具体请求。

三、控制接口 401，检查 API 密钥

HTTP 401 表示请求缺少目标资源所需的有效凭据，含义见 MDN 的 401 说明。这里先确认返回错误的是控制 API，不是面板页面所在网站。

Mihomo API 文档展示了 Authorization: Bearer 方式，其中使用的是配置中的 API 密钥。见官方 API 说明。在面板的对应密钥栏核对当前值，注意旧保存项、多余空格及是否连到了另一份内核配置。

不要把机场账户密码、节点参数或代理入口的用户名密码填进去。请求头可能含授权信息，求助截图应遮住它；分享材料只需保留错误状态和请求路径。代理入口出现 407 属于另一条排查线，可阅读本站代理认证与凭据区别。

四、跨来源错误，先看面板从哪里加载

网页来源由协议、主机和端口共同确定。面板与 API 使用不同来源时，浏览器会检查 CORS；部分请求还会先发送 OPTIONS 预检。MDN 指出，具体失败原因应在浏览器控制台查看，见 CORS 官方说明。

若确认是这一层，核对 Mihomo 的 external-controller-cors 及面板文档。围绕实际需要的面板来源设置允许范围，不直接照搬允许所有来源的示例，也不要用关闭浏览器安全检查代替修复。终端里请求成功，仍不能证明网页的跨来源访问通过了检查。

如果报错来自预检，应记录它和实际 API 请求的区别。只看一条 OPTIONS 成功，不能断言随后读取节点的请求也成功。

五、协议错误与监听错误，不能靠换节点修复

HTTPS 页面请求不安全资源时，浏览器可能按混合内容规则拦截接口请求。MDN 也说明，本机回环地址有特殊处理，所以不能仅凭“页面 HTTPS、接口 HTTP”就断定一定被拦。应以具体提示为依据，见混合内容说明。

需要 HTTPS 控制接口时，按内核和面板文档核对 TLS 监听与证书配置；只把面板里的 http 改成 https，不会自动让原来的监听端口支持 TLS。不要为了消除报错关闭证书校验。

若属于连接被拒绝，先确认内核仍在运行、控制端口确实已监听，地址也没有填成其他设备自己的回环地址。发现监听失败或端口冲突，可参考本站Windows 本地监听排查。不应为了接入面板随意把管理接口开放到公网。

六、恢复后，用读取状态来确认

先观察面板能否读取版本及节点列表，再检查策略组当前选择。官方 API 文档列出只读的 GET /version，可用于核对版本信息；不要借排查之名随意调用更新配置、重启或升级接口。

保持同一个面板和控制地址，一次只改一项已确认有误的设置。版本信息成功，只证明相应请求通过了；若日志或图表仍异常，应继续查看它们各自的请求。面板显示正常，也不能替代实际应用的代理连接验证。

欢迎带着面板名称、内核版本、错误类型和脱敏后的请求路径交流，注明是“页面打不开”还是“页面已加载但 API 失败”，不用提供 API 密钥或完整配置：Telegram 联系我。
