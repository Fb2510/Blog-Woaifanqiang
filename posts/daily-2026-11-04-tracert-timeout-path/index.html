tracert 出现星号就是丢包吗？超时与代理路径怎么判断

小六2026-11-04— 次阅读
机场指南

tracert 出现星号，表示对应探测没有在等待时间内收到回复，不能直接等同于网页数据正在丢失。先看后续跳点和终点是否响应，再确认探测是否与实际应用经过同一路径，才有助于判断代理连接的问题。

作者：小六｜资料核对日期：2026年11月4日

本文讨论 Windows 的 tracert。其他系统的 traceroute、不同模式的 MTR 可能采用不同探测方式，参数和结论不能不加核对地混用。

tracert 在探测什么？

Windows tracert 使用 ICMP 或 ICMPv6 探测，逐渐增加 TTL 或跳数限制，尝试收集沿途设备返回的信息。可以把它理解为用不同的“可经过跳数”观察路径，而不是下载一个网页。

微软 tracert 文档说明，部分路由器不会返回 TTL 到期消息，因此在结果里表现为星号。这意味着工具可能看不到某一跳，不能仅凭该行断言设备没有转发后续流量。

每行的时间是探测回复的往返时间，包含返回过程。不要把相邻两行的数字直接相减，就当成两台路由器之间的准确延迟。

星号出现在哪里，下一步也不同

观察结果 可以确认的范围 下一步
中间出现星号，后续仍有回复 后续一些探测能够获得响应 继续观察终点和应用表现
最后几行持续星号 工具没有收到这些探测的回复 核对终点响应策略与实际连接
某一跳时间高，后续恢复较低 该跳此次回复较慢 不单凭这一行认定转发链路拥堵
终点也异常，应用同时失败 存在值得继续调查的共同现象 记录时间和目标，做同条件对照

例如，中间没有回复、后面又出现正常响应时，不能说从第一个星号开始所有流量都断了。另一方面，星号也不能一概忽略；如果终点和实际应用持续异常，仍需要进一步调查。

为什么“路由器丢包”不一定影响转发？

路由器回应发给自己的探测，与替其他连接转发数据，是需要分开观察的行为。微软的 pathping 文档就举例说明：某些设备会丢弃发给自己的包，但这种情况不影响它们转发其他流量。

这也是看 MTR、pathping 结果时容易误判的地方。中间一行的未响应比例，不能不看后续结果就当成整个应用的丢包率。

探测也可能受到回应限制。Cloudflare 排障文档明确提示，它对 ping 请求的限制可能导致超时。因此，某个目标不回 ICMP，并不足以独立证明它的网页服务也不可达。

在 Windows 中留下一份清楚的记录

可以先用下面的命令观察 IPv4 路径：

tracert /d /4 example.com

把示例域名换成需要检查的目标，只填写域名或 IP，不带网页路径和认证参数。/d 用于停止把中间路由器 IP 反查成名称，/4 限定本次使用 IPv4；具体含义见前述微软文档。

/d 不代表完全跳过 DNS：目标若填写域名，仍需要先找到目标地址。记录输出开头显示的目标 IP，便于核对两次探测是否真的面向同一地址。

如果设备和接入网络确实具备 IPv6，可另用 /6 做对应观察。IPv4 与 IPv6 应分别记录，不能将一边的结果直接当成另一边的路径证据。

等待超时也有设定值。单纯把等待时间调短，可能得到更多星号，并不意味着实际线路突然更差；比较时应保留相同参数。

开了系统代理，tracert 就会经过节点吗？

不能仅凭代理开关这样判断。Windows tracert 探测的是 ICMP 路径，而浏览器的显式代理按另一套机制处理请求。Chromium 代理文档说明，Chrome 的代理选择发生在 URL 层面。

据此，浏览器网页经代理成功，不能直接当成 tracert 使用同一路径的证据。反过来，tracert 出现星号，也不能单独证明那个网页的代理连接失败。

若使用 TUN，需要继续核对内核对探测流量的处理、路由和排除设置。没有确认这些条件前，不要把一份路径输出当成完整的节点中继示意图。接管与分流的区别可看本站规则模式与 TUN 指南。

怎样把路径记录和实际问题对应起来？

先固定目标与时间

记录目标 IP、IP 版本、命令参数和探测时间，同时说明实际应用发生了什么：页面连接失败、下载中断，还是只是客户端健康检查超时。

再做少量、同条件的对照

保持设备和目标不变，仅更换一个接入网络，或在核实应用实际出口后比较节点。不同探测是否经过代理要分别说明，不能把两种路径的数字直接拼成结论。

如果需要较长时段的统计，可以按工具说明使用 pathping 或 MTR；它们会继续发送探测并汇总结果。样本多一些有助于观察持续现象，但不能消除探测回复与业务转发之间的区别。

同时保留实际应用的状态与时间。需要比较日常性能时，可参考本站测速条件与记录方法，不要只截取最差的一行，也不要用单次结果给整个服务排名。

求助前遮住完整公网地址、内部主机名和账户信息，提供必要的跳点、时间和应用现象即可。想交流 tracert 星号、探测超时或代理路径的判断，可以通过 Telegram 联系我。
