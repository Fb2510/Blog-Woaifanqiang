代理显示 200 Connection established，网页为什么还是打不开？

小六2026-11-11— 次阅读
机场指南

看到 200 Connection established 时，先找后面有没有目标请求的 HTTP 状态码。第一行 200 是代理对 CONNECT 建立隧道请求的回应。打开 HTTPS 网页还需要在隧道内完成 TLS 握手，再发送网页请求。停在哪一步，决定接下来查代理入口、证书，还是网站响应。

作者小六，资料核对日期为 2026 年 11 月 11 日。本文适用于通过 HTTP 代理访问 HTTPS 网站，并能在终端或日志中看到 CONNECT 的情况。

代理和网站为什么会各返回一个状态码

通过本地 HTTP 代理访问 https://example.com/ 时，应用先向代理发出 CONNECT example.com:443，请它建立一条到目标主机和端口的通道。代理用 2xx 表示进入隧道模式，常见的状态行就是 200 Connection established。HTTP 标准用状态码判断这一步是否成功。 RFC 9110 的 CONNECT 说明

接下来，应用通过这条通道与目标建立 TLS 连接，核对证书，然后发送 HTTPS 请求。收到的网页状态码对应这一次请求。比如代理答复 200，网站回 403，两条记录可以同时成立，说明应用走到了目标响应阶段。 curl 项目的 HTTP 代理说明

用 curl 把两个状态码分别打印出来

先在客户端找到正在监听的本地 HTTP 或混合端口。下面的 7890 是示例，按实际端口替换。命令在 PowerShell 7.3 或更新版本的默认参数传递模式下运行，使用公开示例站点发出一次 HEAD 请求。

curl.exe -q --proxy http://127.0.0.1:7890 --noproxy '' --head --silent --show-error --connect-timeout 10 --max-time 20 --write-out '\nCONNECT=%{http_connect} HTTP=%{response_code}\n' https://example.com/
$LASTEXITCODE

CONNECT 取代理对建隧道请求的最后一次回应，HTTP 取目标请求的响应码。没有收到目标状态码时，curl 会把零显示为 000。最后单独打印的数字是 curl 退出码，可与错误原文一起保存。即便退出码为零，也要查看 HTTP 状态，因为这个命令允许读取 4xx 响应。 curl 参数手册 · curl 对目标响应码的定义

空的 --noproxy 参数让本次命令覆盖环境变量里的代理排除名单，避免目标恰好被排除。PowerShell 7.3 起的新参数传递模式会保留空字符串。 PowerShell 参数解析说明

根据输出决定先查哪一段

示例输出 先查什么
CONNECT=000 HTTP=000 看错误原文，确认本地代理进程、监听端口及代理类型
CONNECT=407 HTTP=000 核对代理入口的认证要求与应用的代理设置
CONNECT=502 HTTP=000 查代理建立隧道的日志，确认目标地址、端口及到目标的连接
CONNECT=200 HTTP=000 已看到建隧道回应，接着查 TLS、连接重置或等待响应超时
CONNECT=200 HTTP=403 已有目标响应，核对目标路径、访问条件和响应中的请求编号

这些组合用于判断阶段。比如同样出现 502，如果它在 HTTP 一栏，应从目标请求的网关或服务日志查起。记录报错时把字段名和数字一并留下，方便维护者定位。 本站的网关错误排查指南

隧道返回 200，目标却显示 000

如果错误里是 curl 退出码 35，优先看 TLS 握手失败的详细提示。退出码 60 指向证书验证，可以核对域名、设备时间和工具使用的信任来源。退出码 28 表示触及超时限制，需要结合客户端日志判断是在握手还是在等待网页回应。比如只有一个域名报 60，就先检查该域名收到的证书和错误原文。 curl 退出码说明 · 本站的证书错误检查方法

目标已经回了状态，浏览器为什么还在转圈

先把终端测试的地址和浏览器真正失败的地址对齐。比如首页返回 200，但图片、登录接口或文件请求在另一个域名上失败，就在浏览器的 Network 面板记录那条请求的方法、地址和状态。把它与客户端同一时间的连接记录对照，看看两者是否用了相同的代理入口和出站规则。

如果终端显示 HTTP=301 或 302，这条命令会停在收到的重定向响应。可以查看响应头中的 Location，核对浏览器接下来访问了哪个地址。如果新地址换了主机名，分流规则和后续连接结果也可能跟着变化。这样可以把首跳状态与实际卡住的请求对应起来。 curl 手册中的重定向选项

示例域名能通，原来的网站还是打不开

用同一个入口、同一个节点，对原来失败的公开页面做一次对照。示例域名的结果只覆盖那一次请求。HEAD 只检查响应头，有些网站对 HEAD 和浏览器发出的 GET 有不同处理。如果 HEAD 显示 405，可以对确认允许访问的公开页面用普通 GET 比较。若页面依赖登录或其他接口，再核对浏览器里实际失败的那条请求。

切换节点前后保留目标地址、两个状态码和错误原文，尽量只改变节点。若代理入口对目标采取了直连分流，先从客户端记录核实实际出口。多个无关目标都在同一阶段报错时，可以优先检查它们共用的入口和链路。如果只有一个目标反复失败，先收集该目标的时间、状态与错误，交给能查看相应日志的人。
