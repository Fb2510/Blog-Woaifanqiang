关闭机场客户端后电脑不能上网？Windows 代理残留排查

小六2026-10-04— 次阅读
机场指南

关闭机场客户端后，Windows 浏览器突然不能上网，常见排查方向是系统仍指向已经停止运行的本地代理。先检查代理设置和客户端退出方式，再判断基础网络是否异常。重装软件或更换 DNS，不一定能修复留下来的代理地址。

本文面向自己管理的 Windows 10、Windows 11 电脑。单位统一配置的设备，应先核对管理要求，避免误删原本需要的代理或脚本。

作者：小六

软件退出了，为什么代理设置还在？

桌面客户端可以在本机提供一个代理入口，再让采用系统代理的应用连接它。设置中的 127.0.0.1 表示本机，端口号对应本地服务。

假设浏览器仍被设置为连接本机某个端口，但提供这个入口的客户端已经关闭，请求就可能停在本机这一环。此时还没有足够证据说明远端节点故障。

微软说明，Windows 的代理设置分为自动检测、设置脚本和手动配置，VPN 连接的代理还需单独设置。检查位置见 Windows 代理官方说明。

这里有三个动作要区分：关闭窗口、退出客户端、关闭系统代理。具体软件可能把关窗口设为最小化到托盘，不能只凭窗口消失判断服务已经停止。

第一步：先记下设置，再正常退出

如果客户端还能打开，先确认它是否仍在托盘运行，以及系统代理、TUN 的当前状态。通过软件提供的开关关闭自己启用的接管功能，再使用正常退出菜单。

观察退出后系统设置是否恢复。若重新开启客户端就能上网，而退出后再次失败，说明本地入口与退出恢复过程值得检查；这仍不是最终结论。

不要同时启动两个会接管网络的工具。否则一个软件可能恢复了设置，另一个又重新写入，看到的结果会不断变化。

第二步：检查 Windows 的三个位置

进入“设置 → 网络和 Internet → 代理”。不同系统版本的文字略有差异，实际以当前界面为准。

设置项目 怎样判断是否需要处理
手动代理 是否仍指向这次客户端使用的本机地址和端口
使用设置脚本 是否保留了由这次客户端启用的脚本地址
自动检测设置 先保留原有状态，不把它和手动代理混为一项

如果能确认手动代理是自己为该客户端启用的，且现在需要恢复直接连接，可以关闭“使用代理服务器”并保存。脚本也只处理已经确认属于这次客户端的项目。修改前保留原值，避免把单位或其他软件的设置一起清掉。

完成后重新打开一个平时可直接访问的网页。测试目标要固定，不要只看任务栏的网络图标。网页恢复后，再检查常用应用是否也恢复。

只有 Firefox 仍失败，要检查浏览器自己的配置

Firefox 可以使用系统代理，也可以采用手动配置、自动配置 URL 或不使用代理。系统设置恢复后，浏览器若仍保留独立代理，结果可能不同。可参考 Firefox 连接设置说明。

在 Firefox 设置中搜索“代理”，找到连接设置；当前官方文档包含不同界面的入口，搜索设置比照搬旧截图更方便。先记下原配置，再按自己的实际连接需求检查。连接设置还可能提示控制网络的扩展。

其他应用也可能有自己的代理选项。一个浏览器恢复、另一个没恢复，是区分配置范围的线索，不能据此认定宽带时好时坏。

浏览器恢复了，某个后台程序仍失败怎么办？

部分 Windows 程序使用 WinHTTP，它的代理配置需要另外核对。微软的命令文档区分了基本代理与高级代理设置，见 netsh winhttp 官方说明。

熟悉命令行的用户，可以先进行只读查询：

netsh winhttp show advproxy
netsh winhttp show proxy

第一条查看高级设置，第二条查看基本设置；部分系统环境可能不支持前者，应以该系统的帮助和支持情况为准。查询输出不代表所有应用都采用这一配置。

不要看到网上的“网络修复命令”就整段执行。即使重置 WinHTTP，也只处理这一层的设置，不等于恢复浏览器独立代理、TUN 路由及全部网络状态。先确认受影响程序使用哪种连接方式，再决定是否需要恢复相关设置。

哪些情况，应继续查基础网络？

如果关闭自己启用的代理后，多个可直接访问的服务仍失败，可以用同一网络里的另一台设备做对照。另一台也异常时，继续检查路由器、接入网络和服务状态；只有本机异常时，再查本机配置。

若问题只在 TUN 退出后出现，要检查客户端的恢复日志和虚拟网络接管状态。理解这部分，可以看本站的系统代理与 TUN 指南。

下次退出前，保留一个简单习惯

先关闭由自己启用的网络接管，再正常退出，并确认常用网页可用。若每次异常退出都会留下同一设置，记录系统版本、客户端版本和退出方式，供软件维护者定位。
