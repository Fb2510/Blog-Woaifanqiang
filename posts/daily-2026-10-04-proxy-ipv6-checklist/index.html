机场客户端的 IPv6 要关闭吗？入口、出口与 TUN 的检查清单

小六2026-10-04— 次阅读
机场指南

使用机场客户端时，不需要看到 IPv6 就立即关闭它。先判断出问题的是电脑到节点的连接、客户端接收的流量，还是节点到目标网站的连接。三个位置的设置不同，把它们都归结为“IPv6 开关”，容易改错地方。

本文适合 IPv4 连接正常、部分 IPv6 相关连接异常的排查场景，以 Windows 与 Mihomo 内核客户端为例。当前连接正常时，可以先保留默认设置。

作者：小六

节点支持 IPv6，究竟指哪一段？

看到“支持 IPv6”的说明，最好继续确认具体含义。它可能描述接入地址，也可能描述目标连接能力，两者不能直接画等号。

位置 需要核对的问题
本机网络 当前接入网络是否提供可用的 IPv6 路径
本机到机场节点 节点入口是否有 IPv6 地址，协议与路径是否可用
客户端接管范围 应用的 IPv6 连接是否进入客户端
节点到目标网站 实际出口是否能访问目标的 IPv6 服务

节点入口有 IPv6 地址，不代表远端出口一定能访问所有 IPv6 网站。反过来，本机没有原生 IPv6，也不能仅凭这一点判断远端出口能力；要看客户端、协议和服务方提供的实际连接方式。

确认时应问清“入口”还是“出口”，并观察对应连接。节点名称里的“IPv6”只能作为说明线索，不能代替测试。

Mihomo 的几个字段，不是在控制同一件事

顶层 IPv6：内核是否接收相关流量

Mihomo 的顶层 ipv6 字段表示是否允许内核接受 IPv6 流量。它不是 Windows 网卡的协议开关。见全局配置官方说明。

客户端界面上的“IPv6”选项是否对应这个字段，还要查该客户端文档。有的软件会同时修改多项配置，不能只凭相同名称判断影响范围。

节点 ip-version：怎样连接出站地址

节点通用字段 ip-version 控制出站使用的地址版本；对非直连类型，会影响节点服务器使用域名时选择的地址。官方列出了 dual、ipv4、ipv6 及两种优先选项，见节点通用字段说明。

例如，节点域名同时提供两类地址，而当前网络的其中一条路径异常，地址选择会影响连接结果。但把某个节点设为偏好 IPv4，不能推导出所有目标网站的 IPv6 已被系统关闭。

TUN 的 IPv6：还需要接口与路由配合

TUN 文档中的 inet6-address 用于指定虚拟接口的 IPv6 地址，并要求顶层 ipv6 同时启用。自动路由与排除范围还会影响哪些连接被接收。见 TUN 官方说明。

填上一个地址，不等于全部应用流量已经按预期转发。实际仍要核对应用、路由、规则和最终出口，不能只检查配置文件里是否出现了 IPv6 字样。

有 IPv6 地址，就代表这条路一定通吗？

不代表。地址能够解析出来，与相应路径能够建立连接，是两个条件。双栈应用还可能尝试不同地址，选择先建立成功的连接。

IETF 的 RFC 8305描述了 Happy Eyeballs 机制，用不同地址的连接尝试减少等待。具体应用是否采用这一机制、如何实现，仍需查该应用资料。

这也说明：浏览器很快打开网页，可能掩盖了另一条地址路径的异常；一个应用能用，另一个等待很久，不能只根据表面现象认定节点性能差。

按四步排查，避免全系统一起改

  1. 明确失败目标。 记录出错应用、域名、时间和错误类型，区分节点连接失败与目标连接失败。
  2. 查看实际地址与路径。 在客户端日志允许的范围内，检查使用的是哪类地址，以及命中的规则和出口。不要把 DNS 返回的候选地址当成已经建立的连接。
  3. 做一次范围有限的对照。 若怀疑节点入口地址选择，使用客户端支持的相应选项测试，保留原配置；若怀疑接管范围，则核对 TUN 路由，避免顺手改动系统网卡。
  4. 恢复并复查。 同一目标重复测试，观察错误是否稳定变化，再决定是否保留改动。临时恢复正常，只说明这项值得调查。

如果客户端不提供必要的地址记录，可以先做设备或网络对照，再向服务方询问入口与出口支持情况。先说明观察范围，不宜仅凭一个检测页面就判断所有应用的连接去向。

Windows 为什么不建议随手禁用 IPv6？

微软在 IPv6 配置指南中说明，不建议禁用 IPv6 或从接口解绑，因为部分 Windows 组件可能依赖它；该文主要面向高级用户和 Windows Server 管理场景。见微软官方指南。

因此，普通客户端排障应先缩小到相关配置。网上的注册表片段不适合当成所有电脑的通用加速办法，尤其不能同时修改网卡、DNS 与客户端，再把恢复归因于其中一个开关。

怎样确认最后的设置符合需求？

检查常用应用、需要使用的 IPv6 目标，以及局域网服务是否正常；保留修改项目和原值。对于不能核对的连接范围，应明确记录，而不是宣称“全部覆盖”。

需要理解接管与分流，可以结合本站的规则模式和 TUN 指南阅读；解析问题则另见三处 DNS 设置的区别。
